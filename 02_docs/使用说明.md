# 使用说明 · dsh-altare

## 一分钟接入

```powershell
# 1) 接入 profile（会备份 cordis.patch.yml）
powershell -ExecutionPolicy Bypass -File "<项目根目录>\07_releases\install.ps1"

# 2) 配令牌（三选一，见下）
[Environment]::SetEnvironmentVariable("ALTARE_TOKEN", "alt_你的令牌", "User")

# 3) 重启 DSH，然后对 AI 说：
#    “看下我 Altare 上有哪些应用”
```

`install.ps1` 做两件事：把 `01_src` 以 junction 挂到 `~/.dsh/profiles/desktop/node_modules/dsh-altare`，并在 `cordis.patch.yml` 末尾追加插件行（幂等，重复运行不会加第二行）。

## 令牌

控制台 **Team → Settings → API tokens → Create token**：

| 预设 | 包含 scope |
|---|---|
| Deploy from CI | `servers:view`、`servers:power`、`servers:console` |
| Read only | `servers:view`、`servers:activity`、`team:settings:view`、`team:members:view`、`team:logs:view` |
| Custom | 自己勾，要全功能就全选 |

令牌只显示一次。三种存放方式，按优先级：

1. **环境变量**（最省事）：`ALTARE_TOKEN`，用户级或系统级都行，改完要重启 DSH。
2. **dsh 凭据库**（推荐，不进任何配置文件）：在 `~/.dsh/.credentials.yaml` 的 `refs:` 下加一行
   ```yaml
   refs:
     ALTARE_TOKEN: alt_你的令牌
   ```
3. **插件配置**（仅一次性令牌）：`cordis.patch.yml` 里 `config` 下加 `altareToken: alt_你的令牌`。

> 换了令牌不用重启：插件每次调用都重新解析，`cacheTtlMs`（默认 60 秒）只缓存团队与 scopes。

## 工具参数速查

### `altare_whoami`
| 参数 | 说明 |
|---|---|
| `action` | `token`（默认）/ `access` |

返回团队、scopes、`serverIds`、过期时间、令牌来源，以及 `capabilities`（每个工具的每个动作 `allowed` 与否）。

### `altare_apps`
`action` + `app`（list 除外）
`list` `details` `power`（+`signal`：start/stop/restart/kill）`rename`（+`name`/`description`）`reinstall` `startup_get` `startup_set`（+`environment` JSON / `dockerImage` / `startup`）`activity`

### `altare_deploys`
`action` + `app`
`settings` · `deploy`（+`ref`/`sha`/`restart`）· `status`（+`deploymentId`）· `wait`（+`deploymentId`/`timeoutSeconds`/`intervalSeconds`）· `build_settings`（branch/rootDir/version/install/build/start/onPush/previews/healthPath/monitor/cacheStatic/envText/env/previewEnvText/previewEnv）· `preview_create`（+`branch`）· `preview_deploy`/`preview_delete`（+`previewId`）

### `altare_logs`
`action` + `app`
`read`（+`since`/`until`/`q`/`stream`/`process`/`limit`/`before`）· `info` · `job_output`（+`jobId`/`runId`）

### `altare_files`
`action` + `app`
`list`（+`path`）· `read`（+`path`）· `write`（+`path`/`content`）· `mkdir`（+`path`/`name`）· `rename`（+`from`/`to`）· `copy`（+`location`）· `delete`（+`paths`）· `compress`（+`root`/`files`）· `decompress`（+`root`/`file`）· `download_link`（+`path`）· `archive`（+`root`/`paths`/`format`）· `upload_url`（+`directory`）· `pull`（+`url`/`directory`/`filename`/`overwrite`）

### `altare_variables`
`app_get`（+`app`）· `app_set`（+`app`、`envText` 或 `env`、`previewEnvText`/`previewEnv`）· `team_list` · `team_set`（+`name`/`value`/`production`/`preview`）· `team_delete`（+`envId`）

### `altare_backups`
`list` · `create`（+`name`）· `download_link`（+`backupId`）· `delete`（+`backupId`）· `delete_many`（+`ids`）

### `altare_snapshots`
`list` · `create` · `restore`（+`snapshotId`）· `download_link`（+`snapshotId`）· `delete`（+`snapshotId`）· `team_list`

### `altare_network`
`domains_list` · `domain_available`（+`label`）· `domain_create`（+`label`/`kind`/`allocationId`/`appKind`/`custom`/`srvService`）· `domain_check`（+`domainId`）· `domain_update`（+`domainId`/`kind`/`allocationId`/`appKind`）· `domain_delete`（+`domainId`）· `ports_list` · `port_create` · `port_set_primary`（+`allocationId`）· `port_delete`（+`allocationId`）

### `altare_jobs`
`list` · `create`（+`name`/`schedule`/`command`/`timeoutSeconds`/`allowOverlap`）· `update`（+`jobId` 及要改的字段、`enabled`）· `run`（+`jobId`）· `runs`（+`jobId`）· `delete`（+`jobId`）

### `altare_schedules`
`list` · `create`（+`name` 与五个 cron 字段）· `update`（+`scheduleId` 与完整 cron 字段）· `run`（+`scheduleId`）· `delete`（+`scheduleId`）· `task_add`（+`scheduleId`/`taskAction`/`payload`/`time_offset`）· `task_update`（+`taskId`）· `task_delete`（+`taskId`）

### `altare_team`
`members` · `audit`（+`page`/`pageSize`/`actor`/`view`）· `notifications_list` · `notification_create`（+`name`/`kind`/`url` 或 `functionId`/`events`）· `notification_update`（+`notificationId`）· `notification_test` · `notification_delete` · `notification_secret`

### `altare_api`
`method`（GET/POST/PATCH/PUT/DELETE）+ `path`（必须以 `/` 开头，可写 `{tenantId}` 占位）+ 可选 `query`（JSON 或 `a=b&c=d`）+ 可选 `body`（JSON）+ `unwrap`

## 常见剧本

**改环境变量并重新部署**
```
altare_variables(action="app_get", app="my-bot")
altare_variables(action="app_set", app="my-bot", envText="API_KEY=abc\nDEBUG=1")
altare_deploys(action="wait", app="my-bot")
```

**回滚到上一个 commit**
```
altare_deploys(action="settings", app="my-bot")   # 看 deployments 里的 sha
altare_deploys(action="deploy", app="my-bot", sha="9d0e7b2…")
```

**发布前先备份，再恢复**
```
altare_backups(action="create", app="my-bot", name="before-1.21")
altare_snapshots(action="list", app="my-bot")
altare_apps(action="power", app="my-bot", signal="stop")
altare_snapshots(action="restore", app="my-bot", snapshotId="b07a…")
altare_apps(action="power", app="my-bot", signal="start")
```

**发一条控制台命令（模板型服务器）**
```
altare_schedules(action="create", app="survival", name="once",
                 minute="0", hour="0", day_of_month="31", month="2", day_of_week="*")
altare_schedules(action="task_add", app="survival", scheduleId="12",
                 taskAction="command", payload="say 重启中")
altare_schedules(action="run", app="survival", scheduleId="12")
```

**排查线上报错**
```
altare_logs(action="read", app="my-bot", q="error", limit=200)
altare_deploys(action="settings", app="my-bot")
altare_apps(action="activity", app="my-bot")
```

## 配置参考（`cordis.patch.yml` 的 `config`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `baseUrl` | `https://console.altare.gg/api` | API 根地址 |
| `tokenSource` | `auto` | `auto` / `config` / `credentials` / `env` |
| `tokenRef` | `ALTARE_TOKEN` | 凭据引用名，同时是环境变量名 |
| `altareToken` | 空 | 直接写令牌（明文，不推荐） |
| `requestTimeoutMs` | `30000` | 单次请求超时 |
| `maxRetries` | `2` | 429 与 GET 5xx 重试次数 |
| `cacheTtlMs` | `60000` | 令牌自描述缓存时长 |
| `maxOutputChars` | `20000` | 单次输出字符上限 |

## 排障

**工具没出现**：确认 `~/.dsh/profiles/desktop/node_modules/dsh-altare` 指向 `01_src`；`cordis.patch.yml` 里有 `- id: altare`；然后**重启 DSH**。本机实测：往 patch 文件追加内容不会触发热重载，只有重启宿主才会加载新插件。

**`no-token`**：三种来源都没找到。先 `altare_whoami` 看报错里的 `guidance`；环境变量方式需要重启 DSH 才能读到新的用户级变量。

**`scope-missing`**：令牌权限不够。按返回的 `neededScope` 去控制台重新签发（或新建一个 scope 更全的令牌）。

**`TOKEN_ROUTE_NOT_ALLOWED`**：官方禁止 token 调用该端点（成员/账单/令牌/审批/SSH/实时控制台），只能人在控制台做。

**`404` on `/git`**：该应用不是 GitHub 部署型（模板服务器/沙箱没有 git 端点）。

**改了代码没生效**：junction 指向源码目录，但 ESM 模块有加载缓存，重启宿主即可。

## 自检

在项目根目录（含 `01_src`、`06_tests` 的那一层）下依次跑，四项全绿才算通过：

```powershell
node 06_tests/smoke.mjs        # 本地假 API，17 项：鉴权、解析、轮询、错误映射
node 06_tests/apply-check.mjs  # 模拟宿主加载，10 项：注册 13 个工具且 schema 形状正确
node 06_tests/schema-check.mjs # 用宿主真实 dsh-tools 编译，13+13 项
node 06_tests/config-check.mjs # 用宿主真实 schemastery 校验配置，4 项
```

`schema-check` 会去 `~/.dsh/_dbtest` 找 dsh-tools，找不到就把路径作为第一个参数传入。
`config-check` 需要 `@deepseek-ai/schemastery` 可解析：项目根的 `node_modules\@deepseek-ai\schemastery` 是指向 profile 里同版本包的 junction，仅测试用，不进发布包。
`resolve-check.mjs` 是诊断脚本，用来确认模块从 junction 路径能否解析——`dsh-tools`/`cordis` 显示 FAIL 属正常，宿主用自己的加载器注入这两个包。

## 升级与卸载

```powershell
# 升级：改 01_src 后重启宿主（junction 不需要重装）
# 卸载：
Remove-Item "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-altare" -Force
# 再手动删掉 cordis.patch.yml 里的 - id: altare 那一段，重启宿主
```
